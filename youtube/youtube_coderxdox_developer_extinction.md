## 1. 개발 역사의 패턴: "항상 덜 짜는 방향"

| 시대 | 방식 | 당시 반응 |
|------|------|----------|
| 1950년대 | 기계어/어셈블리 (0과 1) | - |
| C 언어 | `printf("hello")` 한 줄 | "기계를 직접 다루지 않으면 개발자가 아니다" |
| C++/Java | 객체지향, 가비지 컬렉터 | "메모리 직접 관리 안 하면 개발이 아니다" |
| Python | `print("hello")` | "장난감 언어, 실제 개발에 못 쓴다" |
| **현재** | **자연어로 지시** | "이건 진짜 개발이 아니다" (매번 틀렸음) |

**패턴**: 추상화 수준이 올라갈 때마다 "이건 진짜 개발이 아니다" 반발 → 결국 더 높은 추상화가 표준이 됨

## 2. 마크다운이 코드를 대체하는 현실

### CLAUDE.md의 역할
- 프로젝트 폴더에 `CLAUDE.md` 마크다운 파일 생성
- 프로젝트 스택, 워크플로우, 규칙 등을 기록
- AI가 이 파일을 읽고 프로젝트 전체 맥락을 이해한 뒤 코드 생성

### 각 도구별 동일한 개념
| 도구 | 파일명 |
|------|--------|
| Claude Code | CLAUDE.md |
| Cursor | Cursor Rules |
| GitHub Copilot | copilot-instructions.md |
| Windsurf | Windsurf Rules |

**이름은 다르지만 역할은 동일** - 마크다운으로 프로젝트 규칙/스타일 가이드를 AI에게 전달

## 3. Skills = 마크다운 파일 묶음

- Claude Code의 "Skill"은 겉보기에 대단해 보이지만, 실체는 **마크다운 파일들의 서브 폴더**
- 특정 상황에서 AI가 참고해야 할 지시사항을 마크다운으로 정리한 파일 묶음
- **AI 코딩 도구에서 가장 강력한 기능 중 하나가 마크다운 폴더** (코드가 아님)

### Skills vs MCP 비교
| 구분 | Skills | MCP |
|------|--------|-----|
| 성격 | 내부적 | 외부적 |
| 역할 | AI가 작업할 때 따를 맥락/규칙/패턴 | AI가 외부 시스템과 통신하는 규격 |
| 비유 | 대본 | USB-C 같은 표준 규격 |

---

## 4. 워크플로우 설계 방식의 변화

### 이전
- Airflow, LangChain 등 프레임워크로 코드로 파이프라인 구현
- DAG 정의, 체인 구성, 에러 처리 등 전부 코드

### 현재
- 마크다운 파일에 자연어로 순서만 적으면 AI가 순서대로 실행
- 돌발 상황에도 유연하게 대처 (유저에게 질문 등)

> 코드로 플로우를 설계하고 구현하던 시대 → **자연어로 플로우를 지시하는 시대**

---

## 5. 개발자의 새로운 역할: 컨텍스트 설계자

### 비유
- **건축가**: 직접 벽돌을 쌓지 않고 설계도를 그림. 설계도가 정확해야 건물이 올라감
- **영화 감독**: 직접 연기하지 않고 배우에게 디렉션을 줌. CLAUDE.md = 대본

> "코드를 잘 짜는 능력" → "AI가 잘 이해할 수 있게 문서를 잘 쓰는 능력" → **"컨텍스트를 잘 설계하는 능력"**

---

## 6. 그래도 기초는 중요하다

### 주의해야 할 착각
- "코드 안 배워도 되겠다" → **위험한 생각**
- 데모까지는 쉽지만, 실서비스로 만드는 것은 전혀 다른 레벨
- 보안, 동시접속, DB 스키마, 캐싱 등은 코드를 이해하지 못하면 **질문조차 할 수 없음**

### 핵심
- 코드를 이해하지 못하면 좋은 컨텍스트를 만들 수 없다
- AI가 짠 코드 검증, 잘못된 방향 수정 → 기본기 필수
- **AI가 더 많이 해줄수록, 기초 지식을 가진 사람의 경쟁력이 역설적으로 올라감**

---

## 7. 결론

- 변하고 있는 것: **직접 코드를 타이핑하는 비중** (확실히 줄어듦)
- 변하지 않는 것: **시스템을 이해하는 능력**
- 개발자라는 직업이 사라지는 것은 아님, 하지만 **요구되는 스킬셋의 무게 중심이 확실히 바뀌고 있음**

> "코드를 직접 짜는 능력" → **"AI가 이해할 수 있도록 컨텍스트를 잘 설계하는 능력"**
