## 핵심 요점 3가지

1. AI 시대에는 **소수정예 인원만으로 유니콘 기업**을 만드는 고효율 구조가 가능 → VC의 역할도 자금 투입에서 **지식과 네트워크 공유**로 진화
2. 모든 의사결정을 **문서화하고 GitHub에 축적** → AI가 정확한 맥락(Context)을 파악할 수 있는 **SSoT 환경** 구축이 AI 네이티브의 핵심
3. 단순 자동화를 넘어 AI가 **사고를 스파링**하고 **최적의 목적지까지 도달하는 내비게이션** 역할을 수행하도록 멘탈 모델 전환 필요

## 1. 델타소사이어티의 새로운 VC 철학

- AI 시대에는 스타트업에 큰 돈이 필요하지 않을 것이라는 가설
- 미드저니 등 소수정예 성공 사례가 앞으로 더 많아질 것
- 스타트업에게 필요한 것은 돈이 아니라 **지식과 네트워크**
- 지식 나눔 모임, AX 리서치 클럽, GTM 리서치 클럽 등 운영

---

## 2. AI 네이티브 업무 시스템: SSoT 구축

### 문제 인식
- 작은 팀에서 의사결정이 빠르게 일어나고 자주 뒤집힘
- 컨텍스트가 계속 미싱(missing) → "나중에 큰 일 나겠다"

### 해결: GitHub 기반 SSoT (Single Source of Truth)
- 모든 의사결정을 문서로 정리 → GitHub 메인 브랜치에 저장
- 브랜치 개념 제거 → **메인 브랜치 하나에 모두 작업** (비개발자도 가능)
- 커밋/푸시 = 구글 드라이브에 올리는 것과 동일한 수준으로 단순화
- 충돌 방지를 위한 파일 구조 설계

### 순환 구조
```
이벤트 발생 → SSoT + AI가 의사결정 지원 → 사람/에이전트가 수행
    → 결과 리캡 → SSoT에 반영 → 다음 이벤트에 활용
```

## 3. End-to-End 업무 방식

- **의존도 해체**: 시작한 사람이 끝까지 책임지는 구조로 전환
- 에이전트가 기존에 못 하던 일(디자인, 기획, 셀링 등)을 보완
- 싱크(Sync) 개념 자체가 뒤집힘 → **결과물만 가지고 이야기**
- 사람과 에이전트의 경계가 무너지고 있음

## 5. KOMPOUND 프레임워크

### 메인 컨셉
- "세상 모든 지식을 다 안다고 A의 문제를 잘 해결할 수 있는 건 아니다"
- **필요한 맥락만 정확히 LLM에게 전달**하는 구조

### 파일 트리 구조
```
KOMPOUND/
├── 시스템/          # Claude Code 행동 원리 제어 (관리자만 수정)
│   └── 의사결정 시 반드시 참조할 코어 문서
├── 워크스페이스/     # 각자 독립 작업 공간 (충돌 방지)
│   ├── 개인A/
│   └── 개인B/
└── 회사 엔티티/     # 의사결정된 내용만 저장
```

- 회사 엔티티만 바꾸면 다른 회사에서도 사용 가능한 구조

## 6. Linear 연동 태스크 배분

### 트리아지 프로세스
1. 아이디어 → Linear 트리아지에 등록 (테스크 후보군)
2. **트리아지 스킬** 실행 → 목록에서 사람 할 일 / 에이전트 할 일 분류
3. 에이전트 할당 태스크 → 자동 수행 → Done 처리 → 결과물은 KOMPOUND에 저장
4. 과거 선택 데이터를 쌓아 판단 기준 학습 중

> "AI가 우리에게 일을 배분하는 시대"

## 7. Product Create 스킬 - 누구나 프로덕트를 만드는 인프라

### 핵심
- 비개발자도 **스킬 하나로** 프로덕트를 만들 수 있는 환경
- 레포지토리 생성 → 서버 세팅 → DB 연결 → 배포까지 자동화
- 외주 개발 프로세스를 그대로 스킬에 녹임 (시나리오 → 비전/목적 → 스펙 → 유저 시나리오)

### 관리 가능한 구조
- KOMPOUND 하위에서 프로덕트 관리
- 데이터 파이프라인 기본 탑재
- 회사 차원에서 얼라인 안 맞는 프로덕트 제거/피드백 가능
- "Replit이나 Lovable을 스킬 하나로 만들어 놓은 것" + **회사 맥락 공유**

### 실제 결과물
- AI Native Camp 리더보드 페이지도 이 스킬로 제작

## 8. 비개발자를 위한 멘탈 모델 변화

### AI Native Camp (팀 어텐션 + 정구봉님과 공동 진행)
- 4일 과정, 캠프 형식 (알려주기보다 함께 문제 풀기)
- 기초: Claude Code 설치, 스킬 사용법, MCP 사용법
- 심화: **컨텍스트 엔지니어링, 컴파운드 엔지니어링**

### 핵심 교육 철학
> "도구로서 AI를 잘 쓰는 법"이 아니라 **"일하는 동료로 인식하고 모든 것을 위임하는 멘탈 모델"**로 바꾸는 것

### 비개발자의 허들
- 설치부터 힘들어함 (터미널 = 해커 화면 느낌에 압도)
- 허들만 넘으면 빠르게 적응

## 9. 자동화를 넘어 - AI 내비게이션의 가치

### 자동화의 한계
- 자동화 도구를 만들어도 3개월~1달 안에 플랫폼에서 대체됨
- 자동화 = 코스트 줄이는 방법 (오래 지속될 일에만 적합)

### AI의 진짜 가치: 목적지 내비게이션
> "내가 원하는 것을 명확하게 깎으면, AI가 내 세계관 밖에서도 목적지를 찾아 도달하게 해준다"

- AI를 통해 가보지 못한 경로 발견
- 목적지를 뾰족하게 깎는 것이 먼저, 자동화는 그다음
- **사고를 스파링하는 대상**으로 AI 활용
