# 섹션 2. 왜 Claude Code인가

> 섹션 1에서 "코딩이 변하고 있다"는 공감을 얻은 뒤, "그래서 어떤 도구를 쓸 것인가"에 대한 답을 제시한다.

---

## 핵심 메시지

> AI 코딩 도구는 자동완성에서 에이전틱 시스템으로 진화했다. Claude Code는 그 중 가장 확장 가능한 도구다.

---

## AI 코딩 도구의 진화 3단계

### 1단계: 코드 예측 및 자동완성
- IDE 자동완성 확장이 보이는 코드를 분석하여 다음 줄 예측
- 반복 패턴에 탁월: REST 엔드포인트 템플릿, 테스트 구조, 공통 알고리즘
- **한계**: 컨텍스트 윈도우가 현재 파일/인접 파일로 제한. 앱 아키텍처 전반의 데이터 흐름이나 크로스 서비스 의존성 이해 불가

### 2단계: 대화형 AI 채팅 인터페이스
- 브라우저 기반 어시스턴트에 대화 기능 추가
- 코드 문제 토론, 스니펫 붙여넣기, 버그 설명, 최적화 질문 지원
- **한계**: 다중 파일 구현 조율이 수동 (파일 붙여넣기, 수정 추적, 복사, 일관성 확인을 사람이 해야 함)

### 3단계: 에이전틱 코딩 ← 지금 여기
- AI가 상위 목표를 수용하여 분해하고 독립적으로 실행
- 전체 코드베이스 읽기, 파일 간 관계 이해
- 명령 실행으로 변경 검증
- 테스트 통과 및 요구사항 충족까지 반복
- **핵심 차이**: 자율성(autonomy)과 범위(scope)

**개발 패러다임 전환:**
- 기존: "코드 작성 → 테스트 실행 → 오류 읽기 → 수정 → 반복"
- 에이전틱: **"목표 정의 → 제안된 변경 검토 → 구현 승인"**

---

## 에이전틱 코딩의 실제 성과

### 개발 타임라인 가속
- 한 엔터프라이즈 고객(Augment Code, Claude on Google Cloud Vertex AI)이 CTO 추정 **4~8개월** 프로젝트를 **2주** 만에 완료
- *"개발자가 학습하는 데 수주가 걸리던 작업이 이제 1-2일이면 완료된다"* — Chief Scientist Guy Gur-Ari

### 신규 개발자 온보딩
- 기존: 수주~수개월 소요. 시니어 개발자의 생산적 시간 손실
- 에이전틱 코딩 도입 후: **수주 → 1~2일**로 단축
- 에이전트 = 전체 코드베이스에 대한 완벽한 기억력을 가진 씽킹 파트너
- 팀원이 **첫날부터** 의미 있는 기여 가능

### 복합 효과 (Compound Effect)
- 비용 대비 불가능해 보이던 작업이 실현 가능해짐
- 수개월 걸릴 기술 부채를 점진적으로 해결
- 더 빠른 반복, 더 많은 실험, 즉각적인 사용자 피드백 대응

## Claude Code의 차별점

### 1. CLI 기반 — IDE에 종속되지 않음
- 터미널이면 어디서든 실행 가능
- 하지만 CLI만 있는 건 아님: VS Code 확장, JetBrains 확장, 데스크톱 앱(Mac/Windows), 웹(claude.ai/code), Chrome 확장까지 다양한 접근 경로 제공
- CLI 기반이라 스크립트화, 자동화, CI/CD 통합에 유리

### 2. 에이전트 루프 — 목표만 주면 알아서 반복
Claude에게 작업을 주면 세 가지 단계를 반복:

1. **컨텍스트 수집**: 파일 검색, 코드 구조 파악, 설정 파일 읽기, import 추적으로 의존성 매핑
2. **작업 수행**: 파일 편집, 셸 명령 실행, 새 파일 생성
3. **결과 검증**: 테스트 실행, 빌드 확인, 오류 분석

이 단계가 작업 완료까지 반복. 사용자는 언제든 중단하여 방향 수정 가능.

5가지 도구 범주, 20개 이상 내장 도구:

| 범주 | 할 수 있는 것 |
|------|-------------|
| 파일 작업 | 파일 읽기, 코드 편집, 새 파일 생성, 이름 변경 및 재구성 |
| 검색 | 패턴으로 파일 찾기, 정규식으로 콘텐츠 검색, 코드베이스 탐색 |
| 실행 | 셸 명령 실행, 서버 시작, 테스트 실행, git 사용 |
| 웹 | 웹 검색, 문서 가져오기, 오류 메시지 조회 |
| 코드 인텔리전스 | 타입 오류/경고 확인, 정의로 이동, 참조 찾기 |

### 3. 확장 레이어 구조 — 필요에 따라 쌓아 올림
Claude Code의 핵심 경쟁력. 기본 도구 위에 7개 확장 레이어를 추가할 수 있음:

| 레이어 | 역할 | 사용 시기 |
|--------|------|----------|
| **CLAUDE.md** | 모든 세션에서 로드되는 지속적 컨텍스트 | 처음부터. 프로젝트 규칙 정의 |
| **Skills** | 재사용 가능한 지식과 호출 가능한 워크플로우 | 반복 작업이 생길 때 |
| **MCP** | 외부 서비스 연결 (Notion, GitHub, Slack 등 100개+) | 외부 도구 필요시 |
| **Subagents** | 격리된 컨텍스트에서 작업, 요약만 반환 | 복잡한 조사/병렬 작업 |
| **Agent Teams** | 여러 독립 세션이 공유 태스크로 협업 | 대규모 병렬 작업 |
| **Hooks** | 이벤트 기반 결정론적 자동화 스크립트 | 예측 가능한 자동화 (린트, 테스트 등) |
| **Plugins** | 기능 패키징 및 배포 | 팀/커뮤니티 공유 |

처음 사용자는 CLAUDE.md만으로 시작. 필요에 따라 레이어를 추가.

### 4. 모델 선택
- **Sonnet**: 대부분의 코딩 작업에 적합. 빠르고 효율적
- **Opus**: 복잡한 아키텍처 결정, 깊은 분석이 필요한 경우
- 세션 중 `/model`로 즉시 전환 가능

### 5. Claude가 접근할 수 있는 것
- 프로젝트 디렉토리 및 하위 디렉토리의 모든 파일
- 터미널 명령 (빌드 도구, git, 패키지 관리자 등)
- git 상태 (현재 브랜치, 커밋되지 않은 변경 사항, 최근 커밋)
- CLAUDE.md 및 자동 메모리
- MCP 서버, Skills, Subagents 등 확장 기능

### Skill vs Subagent vs Agent Team 차이

| 측면 | Skill | Subagent | Agent Team |
|------|-------|----------|------------|
| 정의 | 재사용 가능한 지침/워크플로우 | 격리된 워커 | 여러 독립 세션 |
| 컨텍스트 | 메인과 공유 | 자신만의 윈도우, 요약 반환 | 완전히 독립 |
| 통신 | — | 주 에이전트에게만 보고 | 팀원끼리 직접 메시지 |
| 토큰 비용 | 낮음 | 중간 (요약됨) | 높음 (각각 별도) |
| 최적 용도 | 참조 자료, 호출 가능한 워크플로우 | 많은 파일 읽기, 병렬 조사 | 보안/성능/테스트 동시 검토 |

## 권한 모드와 안전장치

### 도구별 승인

| 도구 유형 | 예시 | 승인 필요 |
|----------|------|----------|
| 읽기 전용 | 파일 읽기, Grep, 검색 | 아니오 |
| Bash 명령 | 셸 실행 | 예 |
| 파일 수정 | Edit/Write 파일 | 예 |

### 권한 모드 종류

| 모드 | 설명 | 사용 시기 |
|------|------|----------|
| **default** | 각 도구 처음 사용 시 권한 요청 | 처음 사용자, 안전하게 시작 |
| **acceptEdits** | 파일 편집 자동, 명령은 요청 | 일반적인 개발 작업 |
| **plan** | 읽기 전용. 분석만 가능 | 코드베이스 탐색, 구현 전 계획 |
| **auto** | 배경 안전 검사로 자동 승인 | 신뢰할 수 있는 환경에서 자율 작업 |
| **bypassPermissions** | 모든 권한 프롬프트 건너뛰기 | 격리된 환경(컨테이너, VM)에서만 |

- `Shift+Tab`으로 모드 순환 전환
- `/permissions`로 세밀한 규칙 설정 가능 (Allow/Ask/Deny)
- deny가 항상 최우선 (예: `Write(.env)` — .env 파일 수정 차단)

### 안전 메커니즘
- **체크포인트**: 모든 파일 편집은 되돌릴 수 있음. `Esc` 두 번으로 복원
- **Plan Mode**: `Shift+Tab` 두 번으로 읽기 전용 분석 모드 진입. 코드 수정 없이 계획 수립

## 커뮤니티와 생태계

Claude Code를 선택하는 또 다른 이유: 도구 주변의 생태계가 빠르게 성장하고 있다.

### 공식 지원
- **Anthropic 공식 블로그**: 지속적으로 가이드, 사례, 베스트 프랙티스 공개 (수집 자료만 25개+)
- **Code with Claude 컨퍼런스**: 2026년 3월 개최. Anthropic이 Claude Code 생태계에 적극 투자하고 있다는 신호
- **공식 문서**: 한국어 문서 포함, 워크플로우별 상세 가이드 제공

### 플러그인/스킬 생태계
- **Oh My Claude Code (OMC)**: 멀티 에이전트 오케스트레이션 플러그인. 커뮤니티 주도로 활발히 개발 중
- **Compound Engineering Plugin**: Every.to에서 개발, GitHub 12,300+ 스타. 반복적 AI 네이티브 개발 워크플로우
- **react-best-practices, supabase-postgres-best-practices, ui-skills**: 프레임워크별 베스트 프랙티스 스킬 패키지
- **claude-mem, session-wrap**: 메모리 관리, 세션 래핑 등 유틸리티 플러그인
- **Playwright MCP, GitHub MCP, Exa MCP, Sentry MCP, Slack MCP**: 다양한 외부 도구 연동 MCP 서버

### 한국 커뮤니티
- **정구봉 (Team Attention)**: 159개 CLAUDE.md, 100개+ Skills 운영. 한국어권에서 가장 활발한 Claude Code 파워유저. LinkedIn에서 지속적으로 실전 노하우 공유
- **한국어 콘텐츠**: 유튜브(빌더조쉬, 실밸개발자, 까칠한AI 등), 블로그(요즘IT, hunslog 등), 교육 과정(모두의연구소 26기 등)에서 한국어 자료가 풍부
- 다른 AI 코딩 도구 대비 한국어 자료 접근성이 높음

### 교육 콘텐츠
- **Maven**: Claude Code for Product Managers (371명+ 수강, $2,500), Go from PM to AI Builder ($2,995) 등 전문 과정 운영
- **유튜브**: 한국어/영어 채널에서 튜토리얼, 사례 공유가 활발
- **블로그/뉴스레터**: Builder.io, Product Talk(Teresa Torres), Lenny's Newsletter 등에서 지속적으로 실전 가이드 발행

### 왜 생태계가 중요한가
- 도구의 기능은 시간이 지나면 경쟁사도 따라잡음
- 하지만 **커뮤니티가 만든 플러그인, 스킬, 노하우, 교육 자료**는 쉽게 복제되지 않음
- 문제가 생겼을 때 검색하면 답이 나오는 환경 = 실무 도입의 핵심 조건
