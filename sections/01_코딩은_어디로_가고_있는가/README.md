# 섹션 1. 코딩은 어디로 가고 있는가

> 발표의 첫 섹션. 청중의 관심을 끌고, "왜 이 발표를 들어야 하는가"에 대한 동기를 부여한다.

---

## 핵심 메시지

> "개발자는 더 이상 코드를 짜는 사람이 아닙니다. 마크다운 문서를 작성하는 사람이죠."

---

## 장표 구성

### 장표 1-1. 타이틀

- 제목: "코딩은 어디로 가고 있는가"
- 서브: "우리가 알던 개발은 끝나고 있다"

---

### 장표 1-2. 코딩의 추상화 역사

추상화가 올라갈 때마다 "이건 개발이 아니다"라는 반발이 있었지만, 매번 틀렸다는 패턴

| 시대 | 방식 | 당시 반응 |
|------|------|----------|
| 1950년대 | 기계어/어셈블리 (0과 1) | — |
| C 언어 | `printf("hello")` | "기계를 직접 다루지 않으면 개발자가 아니다" |
| C++/Java | 객체지향, 가비지 컬렉터 | "메모리 직접 관리 안 하면 개발이 아니다" |
| Python | `print("hello")` | "장난감 언어, 실제 개발에 못 쓴다" |
| **현재** | **자연어로 지시** | **"이건 진짜 개발이 아니다" (매번 틀렸음)** |

- **발표 멘트**: "매번 추상화가 올라갈 때마다 '이건 개발이 아니다'라고 했지만, 결국 더 높은 추상화가 표준이 되었습니다. 지금도 똑같은 일이 벌어지고 있습니다."

---

### 장표 1-4. 마크다운이 코드를 대체하는 현실

각 AI 코딩 도구마다 마크다운 설정 파일이 핵심이 된 현실

| 도구 | 설정 파일 |
|------|----------|
| Claude Code | CLAUDE.md |
| Cursor | Cursor Rules |
| GitHub Copilot | copilot-instructions.md |

- "이름은 다르지만 역할은 동일 — 마크다운으로 프로젝트 규칙을 AI에게 전달"
- **발표 멘트**: "어떤 도구를 쓰든, 결국 마크다운 파일 하나가 프로젝트 전체의 품질을 좌우합니다."

---

### 장표 1-5. 개발자의 새로운 역할

역할 변화의 방향성:

```
코드를 잘 짜는 능력
    ↓
AI가 이해할 수 있게 문서를 잘 쓰는 능력
    ↓
컨텍스트를 잘 설계하는 능력
```

비유:
- **건축가**: 직접 벽돌을 쌓지 않고 설계도를 그림. 설계도가 정확해야 건물이 올라감
- **영화 감독**: 직접 연기하지 않고 배우에게 디렉션을 줌. CLAUDE.md = 대본

- **발표 멘트**: "건축가가 벽돌을 쌓지 않듯, 개발자도 코드를 직접 타이핑하는 것보다 설계와 디렉션이 중요한 시대가 왔습니다."

---

### 장표 1-6. 그래도 기초는 중요하다

> "AI가 더 많이 해줄수록, 기초 지식을 가진 사람의 경쟁력이 역설적으로 올라간다"

- 데모까지는 쉽지만, 실서비스로 만드는 것은 전혀 다른 레벨
- 보안, 동시접속, DB 스키마, 캐싱 등은 코드를 이해하지 못하면 **질문조차 할 수 없음**
- AI가 짠 코드를 검증하고, 잘못된 방향을 수정하려면 → **기본기 필수**

- **변하는 것**: 직접 코드를 타이핑하는 비중 (줄어듦)
- **변하지 않는 것**: 시스템을 이해하는 능력

- **발표 멘트**: "코드를 직접 짜는 비중은 줄었지만, 시스템을 이해하는 능력은 오히려 더 중요해졌습니다. AI에게 좋은 지시를 내리려면, 먼저 무엇이 좋은 코드인지 알아야 합니다."
